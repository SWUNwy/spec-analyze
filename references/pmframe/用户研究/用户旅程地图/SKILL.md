# User Journey Map

Visualize every touchpoint, action, emotion, and pain point a user encounters across their entire experience with a product or service, from first awareness through ongoing use.

## Steps

1. **Define the persona and scenario** — Select a specific user persona and the journey scope (start and end points).
2. **List phases** — Break the journey into sequential stages (e.g., Awareness, Consideration, Purchase, Onboarding, Use, Renewal).
3. **Map touchpoints and actions** — For each phase, document what the user does and which channels they interact with.
4. **Capture emotions and pain points** — Record how the user feels at each stage; identify frustrations and moments of delight.
5. **Identify opportunities** — Highlight gaps, drop-off risks, and areas where the experience can be improved.

## Output Format

A horizontal timeline table with rows for: Phase, User Actions, Touchpoints/Channels, Emotions (high/low curve), Pain Points, and Opportunities.

## 它解决什么问题

### 什么时候该用它？

用户旅程地图最适合那些「知道体验有问题，但不知道问题在哪里」的场景。它能把分散的痛点信息整合成一个可视化的全局视图，让团队看清楚干预的优先级。

🔧

功能改版前

在动手改版之前，先用旅程地图看清楚当前体验全貌，避免局部优化破坏整体流程。

📉

用户流失归因

当数据显示某个阶段流失率高，旅程地图帮助定位是哪个触点造成了用户离开。

🔗

多渠道整合

线上线下、App 与 Web 多入口并存时，地图帮助发现跨渠道衔接的断裂点。

🌟

新服务设计

在设计全新服务流程时，先绘制理想旅程地图，倒推每个阶段的产品功能需求。

📞

售后体验优化

投诉率高、NPS 低的产品可以用旅程地图找到售后流程中最损害信任的节点。

## 来源与历史

### 从服务蓝图到体验全景

用户旅程地图的前身是服务设计领域的「服务蓝图」，随着用户体验设计兴起逐步演化为面向用户视角、强调情绪维度的可视化工具。

1989

服务蓝图概念，Lynn Shostack

哈佛商业评论发表 Shostack 的服务蓝图理论，首次将服务交付过程可视化，聚焦「可见」与「不可见」的服务组件。这是旅程地图的直接前身。

1994

用户体验地图在 UX 领域普及

随着早期互联网产品设计的兴起，以用户视角（而非服务视角）绘制体验流程的方法开始在 UX 设计师群体中流行，情绪维度被引入。

2002

Nielsen Norman Group 标准化

NNG 开始系统研究并发表关于用户旅程地图的指南，确立了触点、情绪、痛点、机会点四个核心维度的标准框架，推动其在企业实践中广泛应用。

2010

Adaptive Path Experience Map

著名 UX 咨询公司 Adaptive Path 为 Rail Europe 设计的「Experience Map」成为行业经典案例，展示了大型旅程地图的完整呈现方式，被广泛引用和模仿。

2020

数字化协作工具集成

Miro、Figma、Notion 等协作工具内置旅程地图模板，使得远程团队可以实时共创地图。AI 辅助分析功能开始帮助团队从访谈数据中自动提取情绪标注。

① 门店设立移动点单**专属取餐区**，物理分流拥堵

③ 高峰期动态调整 **ETA 预估**，减少等待时间不透明带来的焦虑

## 使用步骤

### 六步绘出体验全景

旅程地图的价值在于对齐团队认知，而不只是一张漂亮的图。每一步都要确保基于真实用户数据，最后一步的「行动结论」才是真正目的。

01

确定用户角色

选定一个具体的用户角色（Persona），每张地图只描述一类用户的旅程。

›

02

定义场景边界

明确地图的起点和终点，聚焦一个完整的用户场景，避免范围过大。

›

03

梳理触点序列

列出用户在旅程中接触产品/服务的所有触点，按时间顺序排列。

›

04

标注情绪变化

为每个触点评分用户情绪（正面/中性/负面），连成情绪曲线。曲线低谷是重点。

›

05

识别痛点机会

在情绪低谷处深挖痛点原因，在高峰处识别可以强化的优势体验。

›

06

对齐团队行动

将最高优先级的痛点转化为设计行动项，分配责任人，避免「做完地图就归档」。

✓ 这样做

→基于真实用户调研填写，不要用内部假设替代用户声音

→着重标注情绪，情绪曲线比触点列表更有洞察价值

→每次只聚焦一个用户角色，多角色分开绘制

→地图结束要有行动结论，落地到具体的产品决策

✗ 避免这些

→用内部会议讨论替代真实用户调研来填写地图

→把所有用户类型混在一张地图里，导致信息失真

→只做漂亮的视觉呈现，忽视最后的行动落地环节

→绘制完成后放入文档库，没有定期回顾更新机制
