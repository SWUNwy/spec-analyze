# Mental Models

Map how users think a system works versus how it actually works. Use when users are confused, error rates are high, or you are designing a new interaction pattern.

## Steps

1. **Research** — conduct user interviews or contextual inquiry to understand how users expect the system to behave.
2. **Document the user mental model** — draw a diagram of user expectations, terminology, and assumed workflows.
3. **Document the system model** — draw a diagram of actual system architecture, data flow, and states.
4. **Compare** — overlay both models and identify mismatches (gaps, misconceptions, missing concepts).
5. **Redesign** — for each mismatch, decide whether to change the system to match the user or educate the user via better UI.

## Output Format

Two side-by-side diagrams (user model vs. system model), a gap analysis table listing each mismatch with severity rating, and recommended design changes.

---

用户并不是带着空白的大脑来使用你的产品——他们带着从过去经验中建立的「期待地图」。当产品与这张地图吻合，界面就是直觉性的；当两者冲突，用户就会感到困惑、犯错，甚至放弃。

## 它解决什么问题

### 为什么「聪明的设计师」会做出「让用户困惑的产品」？

设计师理解产品的每一个细节——每一个按钮的逻辑、每一条流程的原因。但这恰恰是陷阱所在。设计师越熟悉系统，就越难以感知「不了解系统的用户」是如何思考的。

用户在接触任何产品时，都会从过去的经验中提取一套「内部表征」——这就是心智模型（Mental Model）。它告诉用户：「这个按钮大概是这么工作的」「这个操作应该会发生这件事」。这些预判来自他们用过的其他产品、现实世界的物理规律、以及文化习惯，而不是来自你的文档或教程。

当产品的实际行为与用户的心智模型一致，界面就是「直觉性的」。当两者冲突，用户不会去怪自己——他们会怪产品「太难用」，然后离开。**心智模型框架帮助设计师系统性地研究用户的预期，然后做出「对的设计决策」而非「聪明的设计决策」。**

## 框架结构

### 三个模型，一个缺口

Donald Norman 在《设计心理学》中指出，任何产品都同时存在三个模型，真正的可用性问题来自三者之间的缺口。

Model 01 · 用户心智模型

用户认为它如何工作

由过去经验、类比推理、文化背景构建。用户从不阅读说明书——他们用「猜测」来操作产品。这个模型可能是错的，但对用户来说是真实的。

Model 02 · 设计师概念模型

设计师希望它如何被理解

设计师脑中的「正确工作方式」。这个模型通常更复杂、更精确，但它存在于设计师的头脑中，无法直接传递给用户。

Model 03 · 系统镜像

产品实际传达的信息

用户唯一能感知的是产品的外在表现：UI 布局、用词、图标、反馈、流程。系统镜像是连接另外两个模型的唯一桥梁。

核心原则

设计师的工作：让系统镜像尽可能接近用户的心智模型——或者，当需要改变用户心智模型时，用系统镜像引导用户建立新的、正确的模型。

心智模型冲突案例

邮件「归档」vs「删除」

大量用户把「归档（Archive）」理解为「放入垃圾桶」——因为他们的心智模型是「把东西收起来 = 不想要了」。Gmail 的设计师心智模型是「归档 = 整理」，但系统镜像没有传达足够的差异化信息。结果：用户归档后找不到邮件，以为被删除，引发大量支持工单。

心智模型对齐案例

下拉刷新（Pull-to-Refresh）

Loren Brichter 在 Tweetie（2009）发明了下拉刷新手势。它之所以立刻「感觉对了」，是因为它匹配了用户的物理心智模型：「把什么东西往下拉然后松手，就会弹回去并重置」——就像老式卷尺或橡皮筋。无需任何说明，用户一次就学会了。

## 适用场景

### 什么时候该用它？

心智模型分析贯穿整个产品设计周期。任何涉及「用户如何理解」的决策，都应该用它来检验。

🔬

新用户研究开始时

在设计任何界面之前，先调研目标用户的现有心智模型——他们用过哪些类似产品，建立了什么预期？

🚪

Onboarding 设计评审

新用户的心智模型最脆弱，也最可塑。Onboarding 阶段是建立「正确心智模型」的黄金窗口，不能只靠功能介绍。

⚠️

用户犯错后的根因分析

当用户频繁在某个操作上出错，首先问：「用户的心智模型是什么？」通常答案不是「用户太笨」，而是「设计误导了预期」。

🔄

重大 UI 改版前

改版会打破用户已建立的心智模型。在决定改之前，评估「打破这个心智模型的代价」和「建立新模型所需的引导成本」。

🧩

跨平台一致性检查

用户在手机上建立的产品心智模型，会带到 Web 端。跨平台的交互矛盾会直接破坏心智模型，造成认知负担。

🎯

竞品分析时的差异化判断

用户在竞品上建立了心智模型，切换到你的产品时会带着那套模型。是顺应还是打破，是设计策略的核心决策之一。

心智模型冲突的后果

Clippy 代表了产品历史上最经典的「设计师概念模型 vs 用户心智模型」冲突。设计师的本意是「主动帮助」，但用户的心智模型是「私人工作空间」。两个模型的根本性冲突使得 Clippy 成为用户最厌恶的功能之一，《时代》杂志将其列为「史上 50 大最糟糕的技术产品」。微软在 2007 年彻底移除了 Clippy。

讽刺的是：20 年后，AI 助手（GitHub Copilot、ChatGPT）做的是几乎相同的事情——主动提供建议。区别在于：这一次，用户的心智模型已经被「智能助手」的概念重塑了，而且用户可以「主动召唤」助手，而不是被动打扰。

Notion 的心智模型策略：匹配物理世界

传统笔记工具（Evernote、Word）的用户有一个强烈的心智模型冲突：「数据库」这个概念对大多数人来说完全陌生。Notion 的洞察是：人们理解「物理桌面」——块状的对象可以被移动、嵌套、重新排列，就像真实的纸张和便签。

Notion 用「Block」（块）作为核心概念，匹配了用户「把东西当作物件来摆放」的心智模型。曾经被传统数据库吓跑的用户，发现 Notion 的操作「感觉像是在整理真实的东西」，从而顺利建立了使用习惯。Notion 的 ARR 从 2019 年的数百万美元增长到 2021 年的超过 2.5 亿美元，在很大程度上归功于这个心智模型的精准匹配。

## 使用建议

### 心智模型设计的五个常见错误

大多数可用性问题，本质上都是心智模型问题。以下是设计师最常犯的五个错误。

01

**用自己的心智模型设计，而非用户的。**「我觉得这个图标很明显」是最危险的设计判断。设计师对产品太熟悉，会失去感知「陌生用户如何理解」的能力。必须通过用户研究来校验，而不是内部讨论。

02

**假设用户会读文档来形成心智模型。**用户不读使用说明，不看 tooltip，不看引导弹窗。他们通过「直接操作」来探索产品，用试错来建立心智模型。界面本身必须传达足够的信息，让用户能「猜对」。

03

**没有充分理由就打破已建立的心智模型。**用户在旧版本 UI 上建立了心智模型，改版会造成「旧地图失效」的认知负担。除非新设计能带来显著价值，否则打破既有心智模型的成本往往超过收益。

04

**产品内部使用不一致的隐喻，破坏心智模型的完整性。**如果产品有些地方用「文件夹」隐喻，有些地方用「标签」隐喻，有些地方用「项目」隐喻，用户无法建立统一的心智模型，认知负担会急剧上升。

05

**不做可用性测试来验证心智模型对齐。**「用户应该能理解」不是验证——只有观察真实用户操作，才能发现心智模型冲突。一次 5 人可用性测试，通常能发现 85% 的主要心智模型问题。

## 来源与历史

### 从认知科学到产品设计：心智模型的跨学科旅程

心智模型（Mental Models）概念由苏格兰心理学家肯尼斯·克雷克（Kenneth Craik）在1943年的著作《解释的本质》中首次提出，指人类用以理解和预测外部世界的内部认知表征。1983年菲利普·约翰逊-莱尔德（Philip Johnson-Laird）的同名专著奠定了认知科学基础，此后这一概念经唐纳德·诺曼（Donald Norman）的引介，深刻渗透进UX设计与产品管理实践，成为理解用户如何感知和使用产品的核心分析框架。

1943

肯尼斯·克雷克提出心智模型原始概念

苏格兰心理学家肯尼斯·克雷克（Kenneth Craik）在《解释的本质》（The Nature of Explanation）中提出，人脑通过构建外部现实的"小规模模型"来进行推理和预测。尽管克雷克在1945年意外去世，他关于心智模型的先驱性论述仍成为认知科学后续发展的重要基石。

1983

约翰逊-莱尔德出版《心智模型》专著

普林斯顿大学心理学家菲利普·约翰逊-莱尔德出版《心智模型》（Mental Models），系统阐述了心智模型的认知机制——人类通过构建情境的结构类比来理解语言、推理和知觉。这部著作将心智模型从一个隐喻式概念发展为具有严格认知科学基础的研究框架。

1988

唐纳德·诺曼将概念引入设计领域

唐纳德·诺曼（Donald Norman）在《设计心理学》（The Design of Everyday Things）中将心智模型作为用户与产品交互的核心解释框架，区分了"设计者心理模型"（设计意图）与"用户心智模型"（用户理解），并提出优秀设计应缩小两者的差距。这一著作使心智模型成为HCI与UX设计领域的基础概念。

2008

Indi Young系统化心智模型研究方法

UX研究者英迪·杨（Indi Young）出版《心智模型》（Mental Models: Aligning Design Strategy with Human Behavior），提出了通过定性研究构建"心智模型图"（Mental Model Diagram）的系统方法，帮助产品团队可视化用户的任务与行为模式，为产品功能规划提供用户认知地图。

2010s至今

产品管理中心智模型的广泛应用

心智模型成为产品经理必备思维工具，不仅用于用户研究，还延伸为一种分析复杂问题、构建清晰认知框架的通用方法。查理·芒格等投资界人士推广"多元思维模型"体系后，心智模型一词在商业与产品圈获得更广泛的语义扩展，涵盖了所有帮助人们做出更好决策的认知框架。
