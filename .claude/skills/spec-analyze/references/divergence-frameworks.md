# Divergence Frameworks

> 发散阶段的多框架路由系统。根据需求意图选择合适的发散框架，从单一框架扩展到多框架，使发散阶段具有多层次、多维度的思考深度。

---

## 选择规则

- 默认：1 个主框架 + 1-2 个辅助框架
- Lightweight 路径：不激活发散框架（自由提问）
- Standard 路径：1 个主框架 + 0-1 个辅助框架
- Full 路径：1 个主框架 + 1-2 个辅助框架
- 只向用户说明主框架名称，辅助框架自然融入提问
- 如果框架冲突，说明冲突来源并给出优先级建议

## 按意图选框架

| 发散意图 | 主框架候选 |
|---------|-----------|
| 探求问题本质 | 第一性原理、5 Whys、抽象阶梯 |
| 扩展可能性 | SCAMPER、反向思考、类比迁移 |
| 理解用户价值 | JTBD、价值主张画布、Kano 模型、用户旅程 |
| 压力测试方案 | 场景压力测试、事前验尸 |
| 重新框定方向 | 重构框架、蓝海战略画布 |
| 方案比较决策 | 加权决策矩阵、RICE/ICE、成本效益分析 |
| 战略定位评估 | SWOT、PESTEL、波特五力 |
| 发现盲点假设 | 反向思考、事前验尸 |
| 完整全景探查 | 5W2H、系统思维 |

## 框架详情

### 第一性原理

- **适用场景**：需求听起来像是继承来的、模糊的、或过度约束的
- **不适用场景**：只需要快速选项对比
- **核心问题**：什么是无可否认的事实？哪些假设是借来的？要让这个成立必须满足什么？
- **产出**：本质变量和重建后的选项
- **示例**：在假设产品功能之前，用户真正的痛点是什么？
- **常见误用**：过度抽象，延误实际选择

### 5 Whys / 根因分析

- **适用场景**：表象可能掩盖深层原因
- **不适用场景**：存在多个独立原因，需要系统建模
- **核心问题**：为什么会发生？那个原因为什么存在？
- **产出**：根因链
- **示例**：为什么用户 onboarding 转化率低？
- **常见误用**：强行归结为单一根因，实际上系统是多因的

### 5W2H

- **适用场景**：需要完整但轻量的全景视图
- **不适用场景**：问题是战略性的，需要权衡分析
- **核心问题**：做什么、为什么、谁、何时、何地、怎么做、多少？
- **产出**：结构化上下文地图
- **示例**：在深入分析前澄清一个新功能的想法
- **常见误用**：变成填表，没有洞察

### 系统思维

- **适用场景**：存在多个参与者、反馈循环、或延迟效应
- **不适用场景**：问题狭窄且局部
- **核心问题**：循环是什么？什么激励在强化当前行为？杠杆点在哪？
- **产出**：因果图或杠杆点
- **示例**：为什么团队执行力持续偏移？
- **常见误用**：过度建模而非做出决策

### JTBD（待完成工作）

- **适用场景**：用户动机或产品价值不清晰
- **不适用场景**：用户身份和目标已经明确
- **核心问题**：用户雇佣这个产品做什么？他们在寻求什么进展？
- **产出**：Job Statement 和期望进展
- **示例**：用户为什么会用这个功能？
- **常见误用**：没有证据地发明 Jobs

### 价值主张画布

- **适用场景**：将用户痛点/收益匹配到产品/服务方案
- **不适用场景**：没有明确的用户群体
- **核心问题**：什么痛点被缓解了？什么收益被创造了？与用户任务如何匹配？
- **产出**：价值匹配地图
- **示例**：分析新功能与目标用户群的匹配度
- **常见误用**：创造乐观的价值主张而不验证

### Kano 模型

- **适用场景**：对用户体验质量进行优先级排序
- **不适用场景**：核心功能还未定义
- **核心问题**：什么是基本型、期望型、兴奋型、无差异型？
- **产出**：优先级分类
- **示例**：哪些行为是必须有的，哪些是惊喜点？
- **常见误用**：把兴奋型特性当作可靠性的替代品

### 用户旅程

- **适用场景**：需要理解步骤、触达点、摩擦点和情绪状态
- **不适用场景**：纯后端或抽象策略问题
- **核心问题**：用户在做之前、之中、之后做了什么？在哪卡住？
- **产出**：旅程地图
- **示例**：描绘用户从发现问题到使用方案的完整流程
- **常见误用**：浅层旅程，对决策无影响

### SCAMPER

- **适用场景**：需要对现有方案做变体扩展
- **不适用场景**：基础方案尚未理解
- **核心问题**：替代、组合、改编、修改、他用、消除、反向？
- **产出**：变体列表
- **示例**：如何让这个交互流程更轻量？
- **常见误用**：只追求新颖性，不关注实用性

### 反向思考

- **适用场景**：被困在传统框架中
- **不适用场景**：用户需要快速执行
- **核心问题**：如何让这个方案失败？相反的路径是什么？
- **产出**：反转洞察和安全措施
- **示例**：如何让这个功能产生糟糕的用户体验？
- **常见误用**：为反叛而反叛

### 类比迁移

- **适用场景**：需要从其他领域获取灵感
- **不适用场景**：精确的领域约束比创造力更重要
- **核心问题**：什么类似系统解决了类似问题？什么可以迁移？
- **产出**：类比候选
- **示例**：用医疗分诊类比需求优先级排序
- **常见误用**：迁移表面特征而非深层结构

### 重构框架

- **适用场景**：陈述的问题可能是错误的问题
- **不适用场景**：用户已经确认了问题框架
- **核心问题**：如果这不是一个功能问题呢？什么框架变化会改变解决方案？
- **产出**：替代问题框架
- **示例**：这是技能质量问题还是状态管理问题？
- **常见误用**：无休止的重构，不收敛

### 抽象阶梯

- **适用场景**：在细节和原则之间移动
- **不适用场景**：只有一个层级相关
- **核心问题**：这为什么重要？具体的行动是什么？
- **产出**：从原则到行动的阶梯
- **示例**：从"更好的发散"到具体的提问规则
- **常见误用**：飘得太抽象

### 场景压力测试

- **适用场景**：需要探测假设和暴露盲点
- **不适用场景**：需求是纯信息收集
- **核心问题**：见下方分类场景
- **产出**：风险注释和条件性建议
- **常见误用**：过度场景导致分析瘫痪

#### 数据与输入极端

| 场景 | 关键问题 | 适用场景 |
|------|---------|---------|
| 空响应 | API 返回空数据时组件如何处理？ | 任何有 API 数据获取的功能 |
| 畸形数据 | API 返回错误类型、缺少字段时——前端崩溃还是优雅降级？ | 严格数据契约的功能 |
| 超长输入 | 用户向 50 字符字段粘贴 10000 字符——截断？校验错误？静默失败？ | 任何表单/输入组件 |
| 特殊字符 | 输入包含 XSS payload / SQL 注入字符串——有清洗吗？ | 搜索、评论、个人资料 |
| 文件边界 | 上传 0 字节 / 2GB / 损坏 / 格式错误文件——各发生什么？ | 文件上传功能 |
| 极端数量 | 表格渲染 10000 行、下拉框 5000 选项——UI 会卡死吗？ | 列表/表格/下拉组件 |

#### 用户行为极端

| 场景 | 关键问题 | 适用场景 |
|------|---------|---------|
| 快速重复 | 用户 1 秒内点 10 次提交——10 次 API 调用？10 条重复记录？ | 任何提交/操作按钮 |
| 多标签混乱 | 用户打开 2 个标签页，分别提交不同数据——哪个状态胜出？ | 表单、仪表盘、编辑器 |
| 流程中途放弃 | 用户在 5 步向导的第 3 步关掉标签页，第二天回来——看到什么状态？ | 多步骤流程、结账 |
| 返回/前进滥用 | 用户填写表单后点浏览器 Back 再 Forward——表单状态还在吗？ | 浏览器历史敏感功能 |
| 后台操作 | 用户提交表单后立即跳转——API 调用完成了吗？Toast 还显示吗？ | 任何异步提交 |
| 离线再上线 | 用户离线填写表单后提交——队列？静默失败？困惑错误？ | 移动端、弱网场景 |

#### 系统与环境故障

| 场景 | 关键问题 | 适用场景 |
|------|---------|---------|
| 网络超时 | API 调用 30 秒后失败——UI 一直转圈？超时提示？重试选项？ | 任何依赖 API 的功能 |
| 部分失败 | 页面需要 3 个 API 调用，2 成功 1 失败——显示部分数据？全部报错？ | 仪表盘、复合页面 |
| Token 过期 | 用户 Token 在会话中过期——丢失未保存工作？静默跳转？ | 任何需要认证的功能 |
| 限流 | API 返回 429——前端盲目重试？显示提示？UI 限流？ | 搜索、轮询、高频 API |
| 三方故障 | 支付网关/地图 API/SMS 服务宕机——整个功能挂掉？优雅降级？ | 依赖第三方服务的功能 |
| 并发编辑 | 两个用户同时编辑同一条记录——后写胜出？冲突对话框？合并？ | 协同/管理功能 |

#### 自定义场景生成

当需求不匹配以上分类时，用以下问题生成压力测试场景：

1. **哪个假设如果错了，会摧毁整个功能？**
2. **一个故意作对的用户会怎么使用这个组件？**
3. **什么外部事件（系统控制之外）会造成最大损害？**
4. **用户可能看到的最令人困惑的错误信息是什么？怎么避免？**
5. **什么会让用户在一次糟糕体验后失去对功能的信任？**

### 加权决策矩阵

- **适用场景**：需要跨标准对比选项
- **不适用场景**：标准未知或值不可比
- **核心问题**：什么标准重要？权重多少？每个选项得分多少？
- **产出**：评分选项表
- **示例**：选择 Lightweight / Standard / Full 路径
- **常见误用**：任意权重带来的虚假精度

### RICE / ICE

- **适用场景**：对功能或计划排优先级
- **不适用场景**：覆盖/影响/信心无法估算
- **核心问题**：覆盖范围、影响、信心、努力
- **产出**：优先级顺序
- **示例**：先交付哪些功能？
- **常见误用**：数字掩盖了脆弱的假设

### 事前验尸（Pre-mortem）

- **适用场景**：在承诺前预判失败
- **不适用场景**：用户只需要创意
- **核心问题**：想象这个失败了。为什么？什么警告信号会出现？
- **产出**：失效模式和缓解措施
- **示例**：这个方案可能在哪三个环节最脆弱？
- **常见误用**：过度谨慎阻碍进展

### 成本效益分析

- **适用场景**：判断努力是否值得
- **不适用场景**：定性因素占主导
- **核心问题**：收益、成本、机会成本、风险各是什么？
- **产出**：带净值的建议
- **示例**：这个交互优化值得投入吗？
- **常见误用**：低估无形收益

### SWOT

- **适用场景**：需要快速战略盘点
- **不适用场景**：需要严谨的市场模型
- **核心问题**：优势、劣势、机会、威胁
- **产出**：战略快照
- **示例**：评估这个方案的可行性
- **常见误用**：泛泛的列表，没有行动

### 蓝海战略画布

- **适用场景**：在策略或产品上做差异化
- **不适用场景**：竞争无关紧要
- **核心问题**：什么要提升、降低、消除、创造？
- **产出**：差异化曲线
- **示例**：让这个产品在同类中脱颖而出
- **常见误用**：忽略执行可行性

### PESTEL

- **适用场景**：需要宏观环境分析来评估外部因素对需求的影响
- **不适用场景**：需求范围窄、受外部环境影响小
- **核心问题**：政治、经济、社会、技术、环境、法律六个维度各有什么变化趋势？哪些可能影响当前方案？
- **产出**：宏观环境扫描矩阵
- **示例**：评估新功能在不同市场的合规风险
- **常见误用**：泛泛列出外部因素但不关联到具体决策

### 波特五力

- **适用场景**：需要评估竞争格局或市场定位
- **不适用场景**：内部功能优先级决策
- **核心问题**：供应商议价能力、购买者议价能力、新进入者威胁、替代品威胁、同业竞争强度——各有多强？
- **产出**：行业竞争态势分析
- **示例**：判断新功能能否成为产品的护城河
- **常见误用**：只做静态分析，忽略竞争动态变化

## 冲突处理

当框架给出矛盾的结论时：

1. 说明冲突的来源
2. 指出哪个标准应该占主导
3. 给出推荐的优先级

**示例：**
> Kano 认为这是兴奋型功能，但 RICE 显示影响低。当前目标是可靠性，RICE 应占主导；保留兴奋型功能后续再做。
