# 中文技术写作规范

适用：spec-analyze 产出的 proposal / design / tasks 三文档、界面文案、API 说明与错误提示。目标读者是研发与测试，写作要求克制、准确、可扫读、可执行。

## 边界：改什么，不改什么

本规范只作用于**可见正文**。以下内容保持原样，不做任何改写：

- 代码字面量、JSON 键名、字段名、枚举值、状态码
- URL、API 路径、命令、配置项、占位符、正则表达式
- 产品官方拼写、用户指定的固定文案与固定引用

## 输出硬约束（v3.3：默认强制）

spec-analyze 产出的 proposal / design / tasks 等文档，**默认**必须通过以下硬约束；违反视为输出不合格，修复后重新输出。自动校验由 `scripts/lint-output-text.js` 提供（S4 门禁要求 error 清零）。

### 必须遵守（违反即不合格）

1. **英文大小写**：按「常用术语写法」表统一（`id→ID`、`api→API`、`json→JSON`、`url→URL`、`http→HTTP`、`ai→AI`、`javascript→JavaScript`、`nodejs→Node.js`、`github→GitHub`、`postgresql→PostgreSQL`、`grpc→gRPC` 等）。
2. **确定错词**：`阀值→阈值`、`布署→部署`、`反回→返回`、`回朔→回溯`、`做为→作为`、`embeding→embedding`、`提示工程学→提示工程`。
3. **引号**：可见正文使用直角引号「」；中文弯引号与 ASCII 双引号视为不合格（代码、引用原文、产品官方拼写除外）。
4. **数量逻辑**：`缩小了 3 倍→缩小到原来的 1/3`；`翻了 1 倍→变为原来的 2 倍`；`不超过 100 以上→不超过 100`；不得自行补充基数、年份或期限。
5. **术语一致**：同一概念使用同一首选术语；首现定义后全文一致（如「闭环」）。
6. **机器内容保护**：代码、JSON 键、URL、API 路径、字段名、枚举、状态码保持原样。

### 必须提示确认（不可自动替换）

- 语境缩写/术语：`JS`、`H5`、`Postgres`、`OAuth`、`k8s`。
- 上下文词：登录/登陆、配置/配制、截至/截止、启用/起用、标识/标示、认证/授权、实时/即时。
- 空泛词：赋能、抓手、沉淀、对齐、对标、拉通、打通、协同、联动、洞察、赛道、心智、调性、战役、链路、势能、兜底、落盘、收口、透传——仅在具有明确业务定义、属于正式术语、引用原文或用户要求时保留，并在首次出现处说明含义。
- 语境词：场景、生态、体系、路径、触点、卡点、布局、矩阵、颗粒度、复盘、梳理、输出、提炼。

### 自动校验

```bash
node scripts/lint-output-text.js docs/spec-analyze/specs
```

结果三级：`error`（默认失败）、`warning`（人工确认，`--strict` 时失败）、`style`（仅提示）。校验器自动跳过代码块、行内代码、URL、链接目标与 API 路径。

## 语义与语气

- 准确先于修辞，清晰先于热闹。一句话只承担一个明确任务。
- 优先说明：是什么、适用于什么、需要做什么、接着看哪里。
- 避免问候式开场、宣传口号、空泛形容与黑话堆叠。
- 默认不直接称呼读者；需要指代对象时使用明确角色（如「开发者」「实施人员」「测试」）。
- 第二人称、感叹号、品牌语气属于风格选择：项目约定或特定界面语境可以覆盖默认规则。

## 结构与句子

- 一个段落承载一个主要信息点。
- 一个句子保持一个清晰主干，不连续堆叠多个条件、动作和例外。
- 列表项保持同一层级、句式和信息密度。
- 标题反映用途（如「配置访问令牌」），不只使用抽象名词（如「介绍」）。
- 删除重复信息，但不删除事实、条件和例外。
- 指代可能不清时，用具体名称替代「该」「其」「此」「上述」。

## 术语一致性

- 同一概念使用同一首选术语，不因追求变化而替换同义词。
- 优先采用项目术语表与产品官方写法。
- 首次出现的缩写给出全称，后文保持同一写法。
- 词语有多个合法含义时，先判断语境，不做全局替换。
- 项目专属术语放入目标项目的覆盖文件，不写进通用规范。

## 高频空泛词与改写建议

以下词语容易掩盖具体动作。仅当**有明确业务定义、属于正式术语、引用原文或用户要求保留**时使用；首次出现处说明实际含义：

| 词 | 建议改写 | 说明 |
|---|---|---|
| 赋能 | 提供 / 直接写能力 | 空泛，无动作对象 |
| 抓手 | 关键措施 | 抽象 |
| 闭环 | 完整流程 / 列出开始、处理、完成条件 | 作为正式术语（如闭环状态机）时需先定义 |
| 沉淀 | 形成 / 积累 / 保存 | 空泛 |
| 对齐 | 统一 / 确认一致 | 视宾语改写 |
| 拉通 / 打通 | 连接 / 贯通 | 空泛 |
| 联动 | 相互触发 / 关联 | 视语境改写 |
| 链路 | 依赖链 / 数据链 | 视语境改写 |
| 洞察 | 分析结论 | 更具体 |
| 兜底 | 写出失败后的具体保障机制 | 抽象 |
| 落盘 | 写入文件 / 保存到本地 | 术语化 |
| 透传 | 原样传给下游 | 术语化 |
| 协同 | 协作 / 配合 | 视语境 |
| 沉淀价值 | 形成的价值 | 空泛 |

「场景」「生态」「体系」「路径」「触点」「卡点」「布局」「矩阵」「颗粒度」「复盘」「梳理」「输出」「提炼」等词依赖语境，不做机械替换；使用前确认它在当前上下文有明确含义。

## 标点与排版

- 中文正文使用全角标点。
- 中文引号默认使用直角引号「」；项目、地区或引用规范可覆盖。
- 完整句式的列表项统一用句号；短语型列表项可以不加，但同一列表保持一致。
- 并列词语用顿号，并列分句按层级用逗号或分号。
- 冒号后应当确有解释、列举或引用，不把每句话拆成冒号列表。
- 破折号、括号、斜线只在关系明确时使用。

### 中文与英文、数字之间的留白

在可见正文中，中文与英文单词、缩写、独立数字、版本号之间通常保留空格：

- `HTTP 请求`、`版本 2.0`、`AI 服务`、`与 PM 协作`、`获取批量 ID`

不机械处理：行内代码、代码块、JSON 键名、URL、API 路径、字段名、命令、占位符、正则、直接镜像接口定义的表头、产品官方拼写。

### 常用术语写法

以下为常见推荐写法，项目或产品官方命名优先：

- `id`/`Id` → `ID`；`http`/`Http` → `HTTP`；`url`/`Url` → `URL`
- `json`/`Json` → `JSON`；`api`/`Api` → `API`；`ai`/`Ai` → `AI`
- `javascript` → `JavaScript`；`typescript` → `TypeScript`
- `llm`/`Llm` → `LLM`；`aigc`/`Aigc` → `AIGC`；`rag`/`Rag` → `RAG`
- `chatgpt`/`Chatgpt` → `ChatGPT`；`openai api` → `OpenAI API`
- `python` → `Python`；`nodejs` → `Node.js`；`github` → `GitHub`
- `postgresql` → `PostgreSQL`；`grpc` → `gRPC`；`graphql` → `GraphQL`
- `websocket` → `WebSocket`；`yaml` → `YAML`；`xml` → `XML`；`jwt` → `JWT`

### 营销与增长领域（Affiliate / Social Marketing）

品牌名（仅匹配小写变体，正确形式不误报）：

- `tiktok` → `TikTok`；`instagram` → `Instagram`；`facebook` → `Facebook`；`youtube` → `YouTube`
- `linkedin` → `LinkedIn`；`pinterest` → `Pinterest`；`snapchat` → `Snapchat`；`telegram` → `Telegram`；`whatsapp` → `WhatsApp`
- `shopify` → `Shopify`；`amazon` → `Amazon`；`paypal` → `PayPal`；`stripe` → `Stripe`
- `appsflyer` → `AppsFlyer`；`kochava` → `Kochava`；`ironsource` → `ironSource`；`admob` → `AdMob`；`pangle` → `Pangle`；`mintegral` → `Mintegral`
- `awin` → `Awin`；`sharesale` → `ShareASale`；`rakuten` → `Rakuten`；`aliexpress` → `AliExpress`；`ebay` → `eBay`；`applovin` → `AppLovin`
- `google ads` → `Google Ads`；`meta ads` → `Meta Ads`；`unity ads` → `Unity Ads`；`commission junction` → `Commission Junction`；`skadnetwork` → `SKAdNetwork`

常用缩写（仅匹配小写变体）：

- 投放/计费：`cpa`、`cpc`、`cpm`、`cpi`、`cps`、`cpe`、`ppc`、`ppl`、`pps`
- 效果指标：`ctr`、`cvr`、`roi`、`roas`、`epc`、`ltv`、`cac`、`arpu`、`arppu`、`gmv`
- 用户/内容：`dau`、`mau`、`wau`、`ugc`、`pgc`、`kol`、`koc`
- 渠道/工具：`utm`、`sdk`、`s2s`、`mmp`、`skan`、`idfa`、`ga4`、`gtm`
- 模式/优化：`seo`、`sem`、`aso`、`saas`、`b2b`、`b2c`、`d2c`

营销常见错词：`affliate`→`affiliate`；`campain`→`campaign`；`converion`→`conversion`；`imprssion`→`impression`；`advertisng`→`advertising`；`markting`→`marketing`；`retargetting`→`retargeting`。

语境词（不可自动替换，仅提示）：`adjust`、`branch`、`impact`、`singular`、`lp`、`att`、`cj` 等可能同时是普通英文词或缩写，需按上下文判断。

依赖语境的写法只提示人工确认：`JS`（简短界面可用，正式正文写 JavaScript）、`H5`（不等同 HTML5）、`Postgres`（可能是正式简称）、`OAuth`（协议家族，不自动补成 OAuth 2.0）、`k8s`（正式文档写 Kubernetes，命令与社区语境可保留）。

## 高频错词

确定错误（可直接修正）：`阀值`→`阈值`；`布署`→`部署`；`反回`→`返回`；`回朔`→`回溯`；`做为`→`作为`；`embeding`→`embedding`；`提示工程学`→`提示工程`。

必须结合语境判断：`登录系统` 但 `登陆月球`；`配置参数` 但 `配制溶液`；`截至 4 月 12 日` 但 `截止日期`；`启用功能` 但 `起用新人`；`标识字段` 但 `标示位置`；`认证`（确认身份）vs `授权`（授予权限）；技术能力通常写 `实时通信`，其他语境 `即时` 可能正确。

## 数字与逻辑

- `缩小了 3 倍` → `缩小到原来的 1/3`，或写明减少比例。
- `从 20% 增长到 30%`：增加 10 个百分点，相对增长 50%——二者不可混用。
- `转化率提升了 5%`：确认是提升 5% 还是 5 个百分点。
- `翻了 1 倍` → `变为原来的 2 倍`。
- `不超过 100 以上` → `不超过 100`。
- 修正表达时**不得自行补充**原文没有的基数、年份、期限或测量结果。

## API 状态词与错误文案

### 状态词按语义翻译，不机械直译

| 英文 | 可选中文 | 注意 |
|---|---|---|
| Success | 已完成 / 已处理 / 请求成功 | 视语义 |
| Invalid | 无效 / 格式有误 / 校验未通过 | 不默认译成「非法」 |
| Unauthorized | 未登录 / 认证未通过 / 缺少认证信息 | 不机械译成「未授权」 |
| Forbidden | 无权限访问 / 当前不允许访问 | 视语义 |
| Denied | 被拒绝 / 未通过 | 视语义 |
| Pending | 待处理 / 处理中 / 待确认 | 视语义 |
| Expired | 已过期 | |
| Missing | 缺少 / 未提供 | |
| Accepted | 已受理 / 已接收，等待处理 | |
| Completed | 已完成 | |
| Failed | 失败 / 处理失败 | |
| Conflict | 状态冲突 / 资源状态不一致 | |
| Bad Request | 请求参数有误 / 请求格式有误 | |
| Timeout | 请求超时 / 处理超时 | |

保持 HTTP 状态、业务状态、任务状态、界面提示之间的区别；不修改状态码、枚举值、字段名与响应原文。

### 参数说明要素

每个参数尽量写清：类型与格式、是否必填、单位、默认值、允许值或范围、缺省行为、与其他参数的依赖或互斥关系。不使用「正常值」「根据情况填写」「相关信息」等无法执行的说明。

### 错误文案结构

按顺序提供：发生了什么 → 哪个对象受影响 → 可能原因 → 可执行的恢复操作 → 仍然失败时需要提供的诊断信息。不把推测写成确定原因，不在没有依据时承诺恢复时间。

## 界面文案

- 按钮说明动作与目标，不重复页面标题。
- 错误提示说明发生了什么、影响是什么、如何恢复。
- 危险操作写清对象、后果与是否可撤销。
- 空状态区分「没有数据」「尚未创建」「无权限」「加载失败」。

## 禁止行为

- 不新增来源没有的日期、数字、时限、能力、条件或结论。
- 不删除前置条件、适用范围、例外、风险、安全警告、兼容性说明或失败处理。
- 不把「可能」「计划」「建议」「通常」改写成确定事实。
- 信息不足时保留原意或标记「待确认」，不自行补全。
- 改写引用、法规、合同、错误原文或用户固定文案时，优先保留原文并将建议单独列出。
